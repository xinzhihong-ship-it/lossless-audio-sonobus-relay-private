# 自建视频中转

视频功能完全自建：SonoBus VST 采集摄像头，服务器只负责中转，观看者使用浏览器。

## 端口

- `19090/TCP`：管理后台、观看网页和发送端 WebSocket 信令。
- `19091/UDP`：发送端 JPEG 视频媒体分片。
- `9000/UDP`：原有 SonoBus 音频 Relay，不改协议。
- `10998/TCP/UDP`：原有 SonoBus Connection Server。

## 地址

```text
管理后台：  http://<公网IP>:19090/admin
观看页面：  http://<公网IP>:19090/video/view?room=SB_<群组名>
```

管理后台会把 SonoBus 音频连接和视频发送连接分开显示。音频在线不代表摄像头在线；视频行会显示 `视频在线`、`连接中`、`摄像头不可用` 或 `离线`，并提供“打开视频”。

## OBS

在管理后台的视频连接行点击“复制 OBS 地址”。在 OBS 中添加 **浏览器** 源（不是“媒体源”），粘贴该地址，画布设为 `1280×720`、FPS 设为 `60`。该地址带 `obs=1`，会隐藏状态文字和边框，只保留透明背景的视频画面；视频源不含音频。

## 发送端流程

1. VST 从已有的 SonoBus 音频服务器配置读取视频服务器 IP，不增加服务器或视频端口输入项。
2. 成功加入群组后，VST 自动打开上次选择的摄像头；设备不存在时选用当前可用摄像头。
3. VST 连接 `19090/TCP` 的 `/video/publish`，用它维持心跳和在线状态。
4. JPEG 帧按 `SBV1` 分片发送到 `19091/UDP`；服务器重组完整帧后通过观看者 WebSocket 转发。
5. 摄像头或网络断开时，后台线程重连；音频处理回调不参与摄像头、JPEG 或网络工作。

视频链路不采集音频，避免和 SonoBus 音频重复。摄像头使用操作系统的普通共享采集模式，不主动独占设备；第一次使用仍需要操作系统授予摄像头权限。

## 部署

`.env` 中保持：

```dotenv
PUBLIC_HTTP_PORT=19090
VIDEO_MEDIA_PORT=19091
UDP_RELAY_PORT=9000
CONNECTION_SERVER_PORT=10998
```

云安全组只需要放行 `19090/TCP`、`19091/UDP`、`9000/UDP` 和 `10998/TCP+UDP`。当前部署不使用公网 `80/443`。
